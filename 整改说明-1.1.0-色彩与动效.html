ZeroOne 壁纸 · 1.1.0 审核整改说明（第二轮）

应用名称：ZeroOne 壁纸 包名：com.zeroone.wallpaper 版本：1.1.0（versionCode 1000001） 开发者主体：zeroone 整改日期：2026-09-29 材料：本说明 + contrast-audit-report.txt（全量色值对比度实测表）

一、本轮 4 条审核意见的处理

# 审核意见（问题类型 / 测试项） 结论 处理方式
1 色彩 · 应用使用的色彩需满足最小对比度要求：图标或标题文字与背景对比度大于 3:1，正文文字与背景对比度大于 4.5:1 不通过 → 已整改 重新定义整套配色并逐处复核，见第二、三节；附全量实测表
2 转场动效 · 建议使用系统转场，页面转场采用淡入淡出的运动方式，不应单帧直接切换，左右平移或上下位移切换，曲线优先使用弹簧曲线 警告（非硬性） 全局复核：无页面级左右/上下位移转场；页面切换走系统转场（淡入淡出）；卡片→大图预览用系统共享元素转场 geometryTransition，曲线 Curve.EaseOut、时长 320 ms。见第四节
3 滑动动效 · 界面滑动到边界位置时（上下滑动到顶部或底部，左右滑动到左边界或右边界），应该有反馈动效 警告（非硬性） 全局复核后已确认全部滚动容器都启用了系统弹性边界反馈 EdgeEffect.Spring。见第四节
4 转场动效 · 全屏页面转场动效时长在 8.5 英寸以下设备不应短于 200 ms，8.5~12 英寸不短于 250 ms，12 英寸以上不短于 300 ms 警告（非硬性） 全屏转场统一 320 ms（> 300 ms，覆盖所有尺寸）；微交互（150~220 ms）不属于全屏转场

判定口径说明：审核指南里 色彩对比度是不通过项（必须改）；转场/滑动动效是警告项（建议）。本轮把不通过项彻底改掉，警告项逐条复核并给出代码位置，便于复审时对照。

二、配色整改方案（问题 1）

原配色以「高级黑 + 粉色强调」为主，问题出在两处硬伤：

  1. 浅色文字压在粉色实底上（实测 2.48:1）—— 粉色 #FF6B6B 太亮，白字/浅灰字压在上面都不达标；
  2. 深色主题里的次级灰文字太暗（实测 3.63~4.09:1）—— #7A7A85 / #9A9AA5 压在 #0F0F12、#1C1D22、#191A1F 上，全部低于正文 4.5:1。

三、复核方法（可独立验证）

新增两个脚本，对源码做静态配对 + WCAG 计算，不依赖人工目测：

# 1) 逐处审计：把每个字色/图标色与它所在样式块声明的背景色配对，算对比度，列出不达标项
python tools\contrast_audit.py
# 2) 全量色值表：输出所有出现的 (前景,背景) 组合及对比度与判定（本次提交的证据文件）
python tools\contrast_report.py > contrast-audit-report.txt

判定阈值与审核指南一致：

  • 正文字号 < 18vp（或加粗 < 14vp） → 要求 ≥ 4.5:1
  • 大号文字（≥ 18vp / 加粗 ≥ 14vp）与图标图形 → 要求 ≥ 3:1

四、动效类意见（问题 2、3、4）复核明细

4.1 页面转场：无左右/上下位移

全工程检索 translate / opacity / animation / TransitionEffect / router 结果：

位置 用途 是否页面转场
Index.ets Tabs 底部四个标签页 否，系统 Tabs 默认转场
HomePage / CategoryPage / MinePage geometryTransition 卡片 → 全屏大图预览的共享元素转场 是（系统共享元素，非位移）

结论：应用内不存在"左右平移/上下位移切换页面"的实现；页面进入退出走系统默认转场。
