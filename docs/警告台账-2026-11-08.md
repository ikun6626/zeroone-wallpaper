## 四、下次更新处理建议

### W-01（必须处理）

1. 给搜索页、登录/注册覆盖层补全屏转场，时长按屏幕尺寸取 200 / 250 / 300 ms（建议统一 250 ms 起，8.5 英寸以下 ≥200 ms）；
2. 全屏预览的开合动画把 150/180 ms 提到 ≥200 ms（尺寸自适应）；
3. 若要一次性收口，抽一个统一 `pageTransition`/转场工具，禁止页面再出现「0 ms 直出」；
4. 改动后必须在 Mate X7 折叠态 + 展开态各复测一次。

### W-02（必须处理）

1. 日报大图由固定 `height(500)` 改为按宽度等比（`aspectRatio` 或 `height = 宽 × 1.35`），保证折叠展开/横屏下不裁切；
2. 给首页加窗口尺寸监听（`windowSizeChange`）或断点，折叠展开时重算卡片列宽与顶部区高度；
3. 若产品只做竖屏手机，需在 `module.json5` 明确 `orientation`，并说明折叠屏展开态策略（注意：声明竖屏**不会**阻止展开变宽，仍需等比布局）；
4. 复测：折叠态↔展开态、竖屏↔横屏，逐屏看图片是否错位/截断/变形/模糊。

## 九、W-03 下次更新处理建议（必须处理）

1. **首选**：把 `CardStatsOverlay.favorite` 改为组件**自己订阅状态**——新增 `@StorageProp('favoriteIds') favoriteIds: string[] = []`，图标直接用 `this.favoriteIds.includes(this.w.id)` 计算，不再依赖父组件传参（与本项目既有约定一致：组件内直接读状态以确保重绘）；
2. **次选（改动最小）**：给 `favorite` 加 `@Prop` 装饰器，使其可被父组件更新；但需同时确认 `@Builder` 按值传参不会拦截刷新，否则仍不生效，故推荐方案 1；
3. 若采用方案 2，建议顺手把 5 处调用点从 `@Builder` 值传参改为按引用传递（`$$`），避免同类问题复发；
4. 修复后必须回归：首页（横滑/精选/瀑布流）→ 搜索 → 合辑详情 → 全屏预览 →「我的」收藏数，五个位置的爱心状态需在两秒内一致同步，且不依赖切页或重启；
5. 补一条防回归用例：收藏后在同一页面停留，断言图标状态与 `favoriteIds` 一致。

## 十、W-03 结论

- 等级「警告」，**不阻断上架**（本次审核已通过），但属可稳定复现的交互缺陷，**下次更新必须处理**；
