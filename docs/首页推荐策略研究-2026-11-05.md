# 首页推荐策略研究

日期：2026-11-05
场景约束：鸿蒙 App / 图片总量约 1600 张 / 按合辑组织 / 后端仅有 viewCount、downloadCount / 无用户画像、无协同过滤 / 日活很小

---

## 0. 结论先行

**首屏不是"推荐"，是"定调"。信息流才是"逛"。**

推荐一套方案，只选这一套：

1. **首屏 16 张 = 10 张人工固定"招牌位" + 6 张每日算法轮换位**（固定位保证质量下限与风格识别，轮换位保证回访有新东西）。
2. **信息流 = 贝叶斯分层平滑的质量分 + 硬性多样性约束 + 尾部 12% 探索**。
3. **不做个性化、不按原始 viewCount 直接排、不按画质排序。** 画质只做"准入门槛"，不做打分项。

一句话公式：

```
final = rerank_diversity(
    0.50 · Q_save + 0.35 · Q_open + 0.15 · Q_editorial
)  ，且首屏 16 张不参与探索
```

## 1. 五种做法的真实效果与证据

证据强度定义：**强** = 有公开论文或工业 A/B 数字；**中** = 有论文但结论不针对本场景；**弱** = 只有工程博客/二手说法；**无** = 找不到公开证据，属于直觉。

| 做法 | 真实效果 | 证据强度 | 关键依据 |
|---|---|---|---|
| 人工精选（首屏） | 小库存下成本最低、质量下限最高；无法规模化到 1600 张的持续排序 | **无公开 A/B** | App Store Today、Pinterest 编辑策展是行业惯例，但没有可引用的对照数据。属于工程共识，不是论文结论。 |
| 按浏览量最高（热度） | 会自我强化：越靠前 → 曝光越多 → viewCount 越高 → 更靠前。头部固化，长尾永不见光 | **强** | 反馈回路会放大热门偏差（arXiv:2007.13019 / CIKM 2020）；真实数据里 20% 热门条目占 86% 以上交互（arXiv:2404.12008）。 |
| 风格多样性轮播 | 能缓解"刷三张就想走"，但**过度多样化同样掉满意度** | **中** | ILS / MMR 是成熟方法（Ziegler 2005；Carbonell & Goldstein 1998）；但 Du 等（IPM 2021）实测：经典后处理多样化会"过度多样化"，且没有任何模型给出的多样性水平贴合用户（R²<0.2）。 |
| 画质优先 | "画质"≠"好看"。分辨率/压缩是硬门槛，构图美感是另一回事 | **中**（仅限美感预测） | NIMA（Talebi & Milanfar, IEEE TIP 2018）能预测人类美感评分的分布，在 AVA 数据集上有效；但**没有任何公开证据**表明按画质排序能提升壁纸 App 的浏览深度或留存。 |
| 个性化 + 探索 | 规模化后收益明确；冷启动无画像时不可用 | **强（但不可迁移）** | Netflix：把个性化系统换成纯热度排序，参与度约 -12%；换成矩阵分解约 -4%（Gomez-Uribe & Hunt, 2015）。反向证据：Dacrema 等（RecSys 2019）复现 7 个神经网络方法，6 个打不过调好的简单基线，其中一个数据集上"推荐最热门"就是最好的。 |

补充两条对本次决策更关键的事实：

- **位置偏差是真实存在的**：同一张相关的结果放在第 1 位和第 5 位，点击率能差一个数量级（Craswell 2008；Joachims 2017 的 IPS 方法就是为此设计的）。所以 `viewCount` 高，很大程度只说明它"出现过很多次、且出现过在靠前位置"，不等于"这张图好"。
- **算法不会自动给你多样性**。Pinterest 的 TransAct 上线后，首页曝光多样性反而下降了 2%~3%，他们靠"随机时间窗掩码"才补回来（arXiv:2306.00248）。结论：多样性必须显式约束，不能指望模型"顺便"做到。

## 2. 1600 张 / 冷启动 / 无画像：落地方案

### 2.1 先决条件（不做这一步，后面全是空中楼阁）

现在只有 `viewCount`（累计值）和 `downloadCount`（累计值）。**这两个数不能直接排序**，因为：

- 累计值 = 上架时长 × 位置权重 × 真实吸引力，三者混在一起；
- 没有曝光数，就没有"率"，只有"量"。

**必须补的最小埋点（4 个字段，一天工作量）：**

| 字段 | 粒度 | 用途 |
|---|---|---|
| `impression` | 图 × 天 | 曝光数，算分母 |
| `detail_open` | 图 × 天 | 点开大图/全屏，算"浏览率" |
| `download` | 图 × 天 | 已有，改成按天增量 |
| `session_cards` | 会话 | 人均浏览卡片数，核心深度指标 |

补不上埋点的临时兜底：`日均浏览量 = viewCount / 上架天数`，并强制 `viewCount ≥ 30` 才允许进排序池，否则一律走人工分级。

### 2.2 首屏 16 张怎么选

**10 张固定 + 6 张每日轮换。** 不做"16 张全算法"，也不做"16 张全固定"。

| 区块 | 数量 | 选法 | 理由 |
|---|---|---|---|
| 招牌位 | 10 | 人工指定，长期不变 | 首屏承担"这个 App 是什么调性"的承诺。人工是最便宜、最可控的质量下限，且不需要数据。 |
| 轮换位 | 6 | 算法选：质量分 Top + 风格互补 + 未在首屏出现 | 回访用户每天能看到 6 张新图（37.5% 新鲜面）。全固定会让老用户 3 秒内判断"没更新"直接退出。 |

轮换位的硬规则：
- 同一张图 30 天内不得重复进入首屏轮换位；
- 轮换位必须覆盖至少 3 个不同风格，且与固定位风格不重复超过 2 个；
- 轮换位**不参与探索**，只从质量分前 30% 的池子里选。

首屏 16 张整体要求：**覆盖 ≥4 个风格，每个风格 ≥2 张**。16 张里不能出现 5 张同风格——那是"合辑页"，不是首页。

### 2.3 信息流打分公式

#### 第一步：分层平滑（1600 张、低日活下的关键）

单品数据极稀疏（可能一张图一天不到 1 次曝光），直接算 `download/view` 会得到大量 1/1=100% 的噪声。必须做两层收缩（经验贝叶斯 / 分层平滑）：

```
全局基准:
  p_save_global = 全库 download / 全库 impression      (兜底 0.05)
  p_open_global = 全库 detail_open / 全库 impression   (兜底 0.15)

风格/合辑层 (g):
  p_save_group = (D_g + β·p_save_global) / (V_g + β)   β = 60
  p_open_group = (O_g + β·p_open_global) / (I_g + β)   β = 60

单图层 (i):
  p_save_i = (d_i + α·p_save_group) / (v_i + α)        α = 20
  p_open_i = (o_i + α·p_open_group) / (i_i + α)        α = 20
```

参数理由：
- `α = 20`：相当于给每张图先垫 20 次"虚拟曝光"，让 1/1 的图不会冲到第一。20 次曝光在本场景约等于 1~2 周的自然量，正好是"开始有信号"的门槛。
- `β = 60`：组层更稳，因为一组几十张图共享同一个风格偏好。
- **降级规则**：若 `v_i < 30`，直接用 `p_save_group` 代替 `p_save_i`；若组层 `V_g < 100`，直接用全局值。

#### 第二步：归一化 + 加权

```
Q_save = p_save_i 在候选池内的百分位      ∈ [0,1]
Q_open = p_open_i 在候选池内的百分位      ∈ [0,1]
Q_edit = 人工分级：S=1.0 / A=0.7 / B=0.4 / C=0.15

S = 0.50·Q_save + 0.35·Q_open + 0.15·Q_edit
```

权重理由：

| 权重 | 值 | 为什么 |
|---|---|---|
| save | 0.50 | 下载是成本最高的动作，最接近真实目标（设为壁纸）。缺点是样本极少，靠 2.3 的分层平滑补稳定性。 |
| open | 0.35 | 样本量比下载大 10~20 倍，是低日活下唯一"算得准"的行为信号，代表缩略图的吸引力。 |
| editorial | 0.15 | 冷启动兜底。纯数据排序会把"高级但小众"的图永远埋掉；15% 的人工票刚好能保住调性，又不会压过真实行为。 |

#### 第三步：画质只做门槛，不做权重

```
if 短边 < 1080 或 长宽比不在 [9:16, 9:21] 或 文件损坏:
    直接过滤，不进候选池
```

理由：画质是"能不能用"的问题，不是"想不想看"的问题。把画质做成加权项，会出现"高清但难看"的图排到前面。NIMA 那类美感模型可以离线跑一遍做 `Q_edit` 的辅助参考，但**不要**让它直接决定排序。

#### 第四步：新鲜度——正确用法是"新增加权"，不是"全局衰减"

1600 张如果是一次性导入的存量，**全局新鲜度衰减是有害的**：它只会让排序每天无意义地抖动，破坏用户"好图在前"的稳定预期。

只有在上新时启用乘性小加权：

```
fresh_i = 1 + 0.3·exp(-days_since_added_i / 7)   仅当 days_since_added_i ≤ 14
```

14 天后自动回落到 1.0。新品另有独立保量机制（见 3.4），不靠这个权重。

### 2.4 排序流水线（伪代码）

```
candidates = 全部图片
  |> filter(画质门槛)
  |> filter(不在本会话最近 50 张 / 不在本地 24h 已见集合)
  |> map(score = 0.5·Q_save + 0.35·Q_open + 0.15·Q_edit, × fresh_i)

// 首屏 16
first16 = 人工固定 10 张 ++ 算法轮换 6 张（Top30% 内按风格互补选）

// 后续流：贪心 + 硬约束
pool = sort_desc(candidates)
out  = first16
while out.size < 60:
    if 每 8 张轮到探索位 and 当前位置 > 16:
        取 1 张「曝光 < 50 或上架 < 14 天」的低曝光图（随机）
    else:
        取 pool 中第一个满足下列全部约束的图：
          - 与上一张风格不同，或连续同风格未达 2 张
          - 最近 12 张内该风格 ≤ 4 张
          - 最近 10 张内该合辑 ≤ 2 张
    out.append(选中图)
```

## 3. 工程约束的具体阈值

| 问题 | 处理 | 阈值 | 依据 / 性质 |
|---|---|---|---|
| 曝光偏差（浏览多≠好） | 用"率"不用"量"；用分层平滑；记录曝光 | `v_i < 30` 时降到组层 | 位置偏差有强证据（Craswell 2008；Joachims 2017）。阈值 30 是工程取值。 |
| 位置偏差残留 | 首屏固定；信息流第 5 位起每 6 张做一次**局部随机交换**（只换相邻 2 位） | 交换比例 100%，扰动小 | 低成本去偏，不需要 IPS 模型。**无公开证据**支持具体比例，属工程取舍。 |
| 同图重复 | 本地已见图集合 + 会话内去重 | 同一图 **24h 内不重复**；会话内**最近 50 张**不重复 | 纯工程约束。本地存储即可，不需要服务端画像。 |
| 同风格连刷 | 贪心重排时硬约束 | **连续 ≤ 2 张**；任意 **12 张窗口内 ≤ 4 张**（33%） | 2 张来自 ILS 直觉（允许对比、不允许"只有一种图"）。**无公开 A/B 证据**，属设计判断。 |
| 同合辑连刷 | 硬约束 | 任意 **10 张内 ≤ 2 张** | 合辑是导航入口，不是信息流单元。 |
| 新图冷启动保量 | 配额制，不靠打分 | 每张新图 **150 次曝光**，7 天内均匀投放；新品总曝光 ≤ 当日总曝光的 **15%** | 参考工业界的 item-level 探索配额（arXiv:2505.09033）。**注意：150 次曝光只能保证"不被埋没"，不足以判定好坏**——判定要放到风格组层面。 |
| 探索位比例 | 只放在第 17 张之后 | **12%**（每 8 张 1 张） | 参考值：成熟系统 2~3%、冷启动 20~30%（均来自工程博客，**证据弱**）。12% 是"库存只有 1600 张、需要让长尾有机会"的折中。 |
| 首屏是否探索 | 不探索 | 0% | 首屏决定去留，不能拿它做实验。 |

补充：`风格` 标签必须先在 1600 张上打出来（建议 6~10 类，人工一天可完成）。没有风格标签，多样性约束无法执行——这是本方案唯一的前置人工成本。

## 4. 必须靠 A/B 才能定的结论

### 4.1 哪些不能靠推理，必须实测

| 假设 | 为什么必须实测 | 主指标 |
|---|---|---|
| 首屏 10 固定 + 6 轮换，比 16 张全固定更能留住回访用户 | 新鲜感与稳定感的平衡点无法先验推导 | 回访用户首屏跳出率、D1/D7 留存 |
| save 权重 0.50 优于 0.35（open 0.45） | 低日活下下载样本太少，理论最优权重不存在 | 人均下载数 vs 人均浏览卡片数（存在 trade-off） |
| 连续同风格 ≤2 优于 ≤3 | 没有公开的分场景阈值 | 深度到达率（浏览 ≥30 张的会话占比） |
| 探索 12% 优于 8% / 15% | 长尾曝光与短期体验的平衡只能在真实流量里找 | 7 日留存 + 长尾曝光覆盖率（基尼系数） |

**不必实测**（直接按工程判断定）：画质门槛、同图 24h 去重、首屏不探索。这些是"做了明显更好、不做明显更差"的确定性改动。

### 4.2 小体量下的低成本验证

日活很小的现实是：**统计功效不够，做不了精细 A/B**。所以策略是"先粗后细"。

**第 0 周：只埋点，不改排序。** 拿到 7 天基线（人均浏览卡片数、首屏跳出率、下载率）。没有基线，后面所有对比都是猜。

**第 1~2 周：一次性上全套方案，用"前后对比 + 会话级 bootstrap"。**

- 分流：按设备 ID 哈希 50/50（若日活 < 100，直接全量切换做前后对比更省事，但必须避开运营活动周）。
- 分析单位：**会话**，不是用户。
- 只看 4 个指标：人均浏览卡片数（主）、人均下载数、深度到达率、次留/7 留。护栏：首屏跳出率、加载时长、崩溃率。
- 统计：固定观察 14 天再下结论，**不要每天看 p 值**（peeking 会显著抬高假阳性）。用 bootstrap 置信区间，或贝叶斯"优于基线概率 > 90%"。

**能检出多大的效应（粗略估算，需按实际方差校准）：**

日活 50、两周 → 每臂约 350 个会话。若人均浏览 20 张、标准差 12~16，则 80% 功效下只能检出 **约 13%~17% 以上的相对变化**。

**含义**：小于 10% 的差异在这个体量下检不出来，不要浪费两周去测。优先测"首屏结构"和"探索比例"这类预期效应大的改动。

## 5. 结论性推荐与取舍

**选：人工定调首屏（10 固定 + 6 轮换）+ 贝叶斯平滑质量分 + 硬约束多样性重排 + 尾部 12% 探索。**

| 备选方案 | 相对本方案的取舍 |
|---|---|
| 纯热度排序（按 viewCount） | 实现最简单，但会放大反馈回路、头部固化、长尾永不曝光。且 viewCount 被位置污染，等于把"排在前面的"再排到前面。**否决。** |
| 纯风格轮播 | 能保证不腻，但会把低质量图也轮上来。多样性应是约束，不是目标函数。**否决。** |
| 画质优先排序 | 画质是门槛不是偏好。按画质排会出现"高清但难看"。**降级为过滤器。** |
| 个性化 + 探索（协同过滤 / 向量召回） | 长期正确，但 1600 张 + 无画像 + 低日活，连用户-物品矩阵都填不满。**现在做等于用噪声拟合噪声。** 等有 500+ 日活、单用户 20+ 行为再谈。 |
| 本方案 | 需要一次性投入：4 个埋点字段、1600 张风格标签、一套重排逻辑。收益是：首屏可控、信息流去偏、长尾有救、且所有参数都能在两周内验证。 |

**最后一条判断**：1600 张、低日活的阶段，排序算法能带来的上限很低。真正决定"用得下去"的是三件更基础的事——首屏第一眼的质量、下滑和预览的流畅度、保存后的即时反馈。排序只负责"不要拖后腿"，别指望它单独救留存。
